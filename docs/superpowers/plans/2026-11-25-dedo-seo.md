# Dedo SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the search-engine work from Wunderland Store (`2c29c28`…`8ba7e7e`) to Dedo: canonical URLs, shared head tags, page titles and descriptions, `noindex` on utility pages, a generated `robots.txt`, a sitemap, and 301/404 status fixes.

**Architecture:** Follow Wunderland's design and names wherever Dedo has the same concept. `base.html` prints every SEO tag from a few template variables. `helpers.canonical_url_for` builds every URL meant for crawlers. `app.py` generates `/robots.txt`. `store.py` serves the sitemap. There are two deliberate deviations. Dedo has no `base_url`, so `canonical_url` is optional and falls back to the request's own scheme and host. The bundled catalogue gives about 56,500 sitemap URLs, over the protocol's 50,000-per-file limit, so `/sitemap.xml` is a sitemap index over numbered parts.

**Tech Stack:** Python 3.14, Flask 3.1, Jinja2, PyMongo 4.16, MongoDB 8.0, `xml.etree.ElementTree`, and the existing smoke runner in `tests/smoke_test.py`.

**Spec:** No separate spec. The source is Wunderland Store at `~/Projects/Python/Wunderland-Store`, `git diff 2c29c28^ 8ba7e7e`. Read the `wunderland/` and `tests/` parts of that diff alongside each task. The SEO step deferred in [the refactor design](../specs/2026-11-22-dedo-refactor-design.md) ("SEO work: No (separate step)") and in [the follow-up plan](2026-11-22-dedo-refactor-follow-up.md) (frozen robots 404, frozen unknown-vendor redirect) is this plan.

## Global Constraints

- Every rendered page stays well-formed XHTML Mobile Profile 1.0, served as `text/html; charset=UTF-8`, with no JavaScript. `Runner.check` already parses every HTML response as XML. New head tags use Dedo's ` />` self-closing style.
- Keep every existing public URL, the `/static/content/...` prefix, and the JSON API (paths, payloads, status codes) unchanged.
- No new runtime dependencies. Build XML with `xml.etree.ElementTree`, as Wunderland does.
- The site name in titles and `og:site_name` is `Dedomil`. The title separator is ` • ` (U+2022 with spaces), as in Wunderland.
- Crawler URLs (canonical link, `og:url`, `og:image`, the sitemap, the robots `Sitemap:` line) are built only with `helpers.canonical_url_for`. Page links stay on `url_for`.
- Verify with `MONGO_DB=<fresh db> .venv/bin/python -m tests.smoke_test` on a disposable database. The suite must pass on `config.yaml.example` and on the variants listed in Task 6.

## Review Focus

- **The real catalogue needs more than one sitemap file.** The bundled dump gives 8,468 games, 38,045 game/resolution pairs and 1,509 vendors, about 56,500 URLs. Every part must stay at or under `SITEMAP_URLS_PER_FILE`, and the parts together must list every URL once. Tested in Task 4 (`check_sitemap_parts`).
- **Descriptions are missing, numeric, contain XML-invalid characters, or run long.** The meta description must still render as valid XML, use the fallback text when empty, and be at most 160 characters. Tested in Tasks 2 and 3.
- **A game has no `date`, or a date that isn't a datetime.** The sitemap must still list the game, without a `<lastmod>`, and must not return a 500. Tested in Task 4.
- **Vendor names contain `/`, `&` or spaces.** Sitemap and canonical URLs must use the same query form as the vendor list links (`/games/vendor?name=`) and must be escaped in XML. Tested in Tasks 2 and 4.
- **`canonical_url` has a path prefix or a trailing slash.** Canonical URLs must keep the prefix and never produce `//`. Tested in Task 1.

### Task 2: Shared head tags, canonical link and noindex

**Files:**
- Modify: `dedo/helpers.py`, `dedo/app.py` (context processor, new filter)

**Interfaces:**
- Consumes: `helpers.canonical_url_for` (Task 1).
- Produces: `helpers.CANONICAL_ARGS = {'store.vendor_games_query': ('name', 'page')}`.
- Produces: `helpers.canonical_for_request() -> str | None`. It returns `None` outside a matched route. Otherwise it keeps `request.view_args` and only the query args in `CANONICAL_ARGS` for the endpoint. `page` is dropped when it equals 1 or isn't a positive int, whether it comes from `view_args` or from the query. Other kept args are dropped when empty.
- Produces: `helpers.meta_description(text, fallback: str = '') -> str`.
  - Converts a non-string `text` with `str()` and treats `None` as empty.
  - Strips characters matched by `XML_INVALID_CHARACTERS` and collapses whitespace.
  - Returns `fallback` when the result is empty.
  - Over 160 characters, cuts at the last space at or before 157 and appends `...`.
  - Registered in `app.py` as the template filter `meta_description`.
- Produces: `helpers.og_image_for(game: dict | None) -> str | None`. It returns the `canonical_url_for('content', ...)` URL of the game's splash (`images/splashes/<file>`), else its screenshot (`images/screenshots/<file>`), using `image_filename` as the templates do. Otherwise it returns `None`.
- Produces: context-processor names `canonical_url` (the function `canonical_for_request`), `og_image_for`, and `google_site_verification` (`config.get('google_site_verification')`).
- Produces: `base.html` template variables, documented in a `{#- ... -#}` header comment as in Wunderland's `base.html`:
  - `meta_description`: defaults to `SITE_DESCRIPTION` below.
  - `noindex`: defaults to false. When true, it prints `<meta name="robots" content="noindex, follow" />` and drops the canonical link and `og:url`.
  - `og_game`: defaults to undefined. It is the game used for `og:image`. With no image, `og:image` is left out.
  - `og:title` is always `self.title()|trim`.

Site description copy: `Free Java and Symbian games for classic mobile phones, sorted by screen resolution.`

Disallow: {config['api_prefix'].rstrip('/')}/
Disallow: /static/content/files/
Sitemap: {canonical_url_for('store.sitemap')}
